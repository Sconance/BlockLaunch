# Front UI 复刻状态

Front 的目标是保留旧紧凑界面的布局与操作路径，同时只通过接口调用同级业务模块。`Front/` 不引用 `MainWindow/`；旧 UI 与 Front 可分别移除并独立编译。

## 已接通

- `FrontWindow`：1060×740 紧凑无边框窗口、48px 自定义标题栏、启动/下载/设置/更多导航、最大化/还原/关闭和状态栏。
- 启动页：账号模式卡、离线/微软/MUA 操作、已安装版本选择、启动/停止、版本展开、安装入口、整合包导入入口。
- 下载页：原版游戏、Mod、整合包、数据包、资源包、光影包、本地整合包、模组加载器分类；分类页复用下载和资源业务。
- 版本管理：概览、启动设置、加载器修改、Mod/资源包/光影/存档、本地资源切换与导入、整合包导出；真实写入均经过 `IFrontVersions`。
- 内容中心：搜索结果列表、图标/标签/下载量、详情页、兼容版本列表、外部目录下载入队和分页。
- 设置页：游戏目录/Java/内存/窗口尺寸、高级启动设置、网络与下载、主题/背景、存档保护。
- 日志页：Front 实时脱敏日志和当前实例 `logs/latest.log` 末尾读取。

## 有意保持的差异

- Front 没有复制旧 UI 的内部控件树；视觉通过独立 XAML 重建。
- 微软 WebView2 授权、关闭等待、DPI、主题切换、真实游戏启动和下载操作仍需要 Windows 原生验收。
- 资源搜索和加载器版本查询依赖网络；网络失败时显示错误，不伪造结果。
- 日志页不自动读取未选中的实例，也不会自动安装或自动导入资源。

## 尚未完整复刻，不应删除旧 UI

已接通主要页面不等于旧功能全量迁移。以下内容仍需要代码工作，不只是测试：

- 实例卸载、资源更新与事务回退、收藏管理、整合包升级。
- 在线皮肤头像、完整 Java 管理器、存档备份列表与恢复操作、扩展菜单页面。
- 旧下载网格/列表切换、版本列表分组和逐项操作、各弹窗的像素级间距与样式。

这些差异不能标记成“全部 UI 已完成”；现有资源下载只保存到外部目录，不能冒充安装到实例。

## 验证边界

Linux 开发环境只完成了 WPF 交叉编译、业务断言和前端隔离构建，不能替代 Windows 视觉验收。Windows 验收前保留根目录 `AGENT.md`；通过后按文件要求删除。

### 最新克隆与脚本增量

代码新增版本设置→修改→复制独立实例，以及导出→启动脚本。Front 使用共享克隆服务与脚本导出服务，脚本运行保留配置目录并在 Front 内确认启动，不会自动切换到不匹配的游戏目录。

用户要求本次不做 Linux 本地测试；这些增量尚未编译或运行。较早的交叉编译成功不能代表当前提交通过。Windows agent 按 `FRONT_UI_WINDOWS_TEST.md` 进行构建、修复和验收；当前仍不满足删除旧 UI 的条件。
