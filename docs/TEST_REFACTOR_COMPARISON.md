# test 与 refactor 的结构比较

本轮以 `test` 的 `32a3ad1` 为起点，参考远程 `refactor` 的 `db0ab6a`，只修改 `test`。两者已有独立提交历史，没有执行整分支合并、版本升级或 Release 发布。

| 方面 | 本轮 test | refactor 参考快照 |
| --- | --- | --- |
| 原生窗口 | 保留精简的 MainWindow shell | 仍有 MainWindow partial 功能文件 |
| 页面布局 | 九个独立 XAML 视图与强类型动作路由 | 较多页面通过 UI partial、构建器和对话框组件组织 |
| 显式依赖 | 账号头像、账号面板、加载器概览、网络设置、键盘提示、窗口装饰六个原模块不再接收完整工作区 | 多个控制器直接接收控件、状态读取函数或回调 |
| 复用组件 | 引入游戏窗口行为、实例搜索、离线皮肤包、启动脚本四个组件及账号状态记录 | 这些组件的参考实现来源 |
| 展示模型和表单 | Models、Views/Forms、Views/Shared 与控制器分开 | 已有 Models、Builders、Views 等分类 |
| 版本设置细分 | 仍有较大的 VersionSettingsController 和 InstancePagesController | 已有更细的版本页面构建器、启动参数与整合包对话框组件 |
| 耦合限制 | 其他应用协调模块仍使用 LauncherWorkspace | 仍有窗口 partial 与共享窗口状态 |
| 版本 | 保持 0.20.2，不发布正式程序 | 快照标记 0.21.0 |

本轮吸收小组件与明确依赖的做法，同时保留 test 的窗口/独立页面边界。版本号大小不能用来判断结构优劣；两条分支的 UI、文档和少量 Core 改动尚未完全对齐。

下一步适合按实际功能继续拆分版本设置的概览、启动选项、加载器修改、Mod 管理和导出；之后再收窄资源工作区、任务协调与启动协调的依赖。不要为消除一个工作区参数，换成包含整个工作区所有成员的巨型接口。

本轮对 test 执行构建和回归检查；未对 refactor 重新执行完整验证，不能据此断言其运行稳定性优于或低于 test。真实微软/MUA 人工授权及完整游戏启动矩阵仍需单独验收。
