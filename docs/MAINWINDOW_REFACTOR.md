# MainWindow 职责拆分记录

## 目标与边界

将页面布局、页面状态和异步交互移到独立组件。`MainWindow` 负责组合组件、窗口生命周期，以及与现有启动、认证和下载服务的衔接。

本轮不改变认证协议、实例数据、配置格式和发布版界面。没有找到截图所说的 TODO；下列计划基于当前主分支实际代码，不能视为原贡献者的任务清单。

## 已完成的第一批迁移

| 组件 | 责任 | 主窗口保留的职责 |
| --- | --- | --- |
| `Views/AccountPanelView.cs` | 登录方式、头像、离线输入和身份面板布局；显示状态更新 | 提供已有控件和认证/管理回调 |
| `Views/HomeWelcomeView.cs` | 欢迎区布局 | 判断是否使用默认欢迎区 |
| `Views/ResourceSearchHeader.cs` | 搜索、筛选、收藏和视图按钮排列 | 查询条件、搜索执行和收藏操作 |
| `Views/LoaderConfigurationView.cs` | 加载器选择控件与安装意图事件 | 交给 Presenter 管理 |
| `Presentation/LoaderConfigurationPresenter.cs` | 官方版本目录读取、浏览取消和选择状态 | 接收选择结果，调用既有下载队列 |
| `Presentation/VersionRow.cs` | 展示模型 | 提供版本数据 |

这些组件不是 `partial MainWindow`，不接收 `MainWindow` 对象。视图通过控件输入、回调或事件连接应用行为；加载器 Presenter 通过 HTTP 客户端提供器和安装意图回调连接已有逻辑。窗口关闭时解除 Presenter 事件订阅并取消请求。

保留现有 XAML 命名控件可以继续使用原有绑定与处理器；后续迁移整体页面 XAML 时，再逐步收回控件的创建权。不要为了减少行数而复制一套认证或安装流程。

## 尚未迁移

1. `VersionSettingsUI.cs`：设置页布局、保存、模组管理和导出混合，需先分出页面与应用操作接口。
2. `FeatureUI.cs`、`SketchUI.cs`：实例选择和管理布局仍与主窗口状态相互引用。
3. 资源详情、收藏夹与资料库：需要独立页面及明确的当前实例/项目上下文。
4. 任务、诊断与全局设置：继续收拢各自状态和事件生命周期。
5. `MainWindow.xaml.cs`：页面迁移稳定后，再提取启动协调和账号协调逻辑。

因此，目前不能声称 MainWindow 已全部拆完。后续以独立模块和回归结果为验收单位，而非单纯统计文件数或单文件行数。

## 验证方式

沿用隔离配置下的账号、页内交互、资源浏览与下载、加载器和工作流检查。测试已改为访问独立控件的公开契约，不再依赖原来主窗口里的账号字段或加载器控件元组。

真实微软/MUA 授权与完整游戏启动矩阵未重跑；组件检查和真实资源下载不能代替这些验收。此批重构尚未发布，不覆盖现有 Release 与本地正式 EXE。
